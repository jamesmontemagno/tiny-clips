# tinyclips-media

`MediaService::authorize(parent, requested_kind)` is the only interactive operation. Call it from a local gesture on the GTK main context, never from Agent Control. A specified kind limits the portal to a monitor or to a window; `None` allows either for explicit reusable sharing. It verifies one real PipeWire frame and retains the non-persistent ScreenCast session and a portal-issued remote. `single_capture()` shares recorder controls but isolates the local action's grant from agent discovery. Drop that service when the local capture ends. The grant ID is random and session-local. `target()` exposes negotiated raster dimensions, not the portal's compositor-space size, desktop origin, scale factor, stable device ID, or PipeWire node ID. A `Closed` signal invalidates the grant; `revoke().await` closes it explicitly.

Use `snapshot(id, screenshots_dir)`, `start(id, videos_dir, AudioOptions { microphone, system })`, `pause`, `resume`, and `stop` as async methods on that same main context. `stop` and `snapshot` return the newly published path. `snapshot_region(id, dir, Option<Region>)` and `start_region(id, dir, audio, Option<Region>)` accept a half-open rectangle in **this stream's raster**. Bounds are checked against the last verified raster and again during negotiation. Do not map a desktop-global physical-pixel request to a stream without independently verifying that mapping. `status()` is synchronous. GStreamer, codec probes and disk operations run on worker threads. No method except `authorize` displays a picker.

The application supplies absolute, user-owned private library directories (0700). Screenshot and video files are published without replacement (0600). Only the explicitly opted-in Pulse sources are opened: the default non-monitor input for microphone, and the named monitor of the default output for system audio. Missing/changed routes fail the take rather than substituting a different source. Two enabled inputs are mixed into **one** stereo AAC track; zero inputs produce video-only MP4. No input-device nodes, shell commands, external FFmpeg, network, GPU, or desktop enumeration are used.

Video is variable-rate under load: a bounded drop-old queue keeps the newest real acquisitions, and `videorate` is drop-only (no duplicate frames to fabricate coverage). Audio is not leaky. The enabled sources use the same pipeline clock; their actual 48 kHz stereo PCM buffers are intersected in sample time before a non-live mixer receives matched slices. A common initial A/V barrier avoids an early single-input mix. A lagging/changed source, unbounded wait for overlap, or material loss of sample coverage fails the take rather than treating timed silence as real audio. Pauses stop acquisition; paused monotonic time is excluded from expectations. On normal stop the service checks the input/encoded spans, real audio sample coverage and remuxed playable duration against confirmed active time **before** publishing. Explicit recovery may produce a partial recording.

Live recordings request a keyframe every 10 seconds for `splitmuxsink`. Completely closed fragments are synced and committed as `ready-*.mp4` under a private `.take-<uuid>` directory. Each `clock-*` companion records the original keyframe's pipeline running time so that remux never compresses legitimate gaps between variable-rate segments. `open-*.mp4` may be torn and are never trusted for recovery. Normal stop sends EOS; closed fragments are read one at a time with `qtdemux`, then their encoded H.264/AAC samples are remuxed via `appsrc` and `mp4mux` without re-encoding. The finalizer uses real packet timestamps rather than trusting the advertised duration of an empty terminal track; unmatched A/V tail samples are trimmed to their common playable interval. Successfully published normal takes release their working files. `recoverable_takes(videos_dir).await` lists unlocked interrupted takes with closed segments. After failure or interruption, `recover(take_dir).await` remuxes only the contiguous committed fragments, refuses active takes, and never overwrites a prior result. Any finalization failure leaves the fragments intact. After durable successful publication, the take is retired from startup discovery and the consumed closed segments are removed. Any uncommitted tail or unexpected file remains in a private `.recovered-*` folder; an empty retired folder is removed. There may be nothing recoverable if the first fragment never closed; remuxing needs sufficient additional free space for the output.

## Runtime plugins

GStreamer 1.x core, `queue`, `fdsink`, `videoconvert`, `videoscale`, `videorate`, `videocrop`, `pngenc`, `pipewiresrc`, PulseAudio (`pulsesrc` and `pulsedeviceprovider` when audio is requested), `audioconvert`, `audioresample`, `audiomixer`, `h264parse`, `aacparse`, `splitmuxsink`, `appsink`, `appsrc`, `mp4mux`, `qtdemux`, `videotestsrc`, and `audiotestsrc`. H.264 candidates are software `openh264enc` (with functioning OpenH264 runtime), `x264enc`, `avenc_h264`, and `avenc_libx264`. Audio needs one working AAC encoder (`fdkaacenc`, `voaacenc`, `avenc_aac`, `faac`). Element existence alone is not sufficient: the recorder tests the encoder/parser with actual buffers before opening the capture inputs. No AAC encoder is needed for a silent take.

## Synthetic checks on Linux

```sh
cargo test -p tinyclips-media -- --test-threads=1
tinyclips-media-check --synthetic --seconds 3 --output-dir "$XDG_DATA_HOME/tinyclips/media-check" --audio --pause
```

For a reproducible slow-encoder canary add `--stress-video-ms 250 --seconds 12` (only synthetic input accepts this fixed, bounded delay; use `--seconds` only once). The diagnostic logs active/paused wall time, GStreamer running time, first/last input and encoded timestamps, real sample coverage and gaps, committed fragment durations and the final mux timeline. Capture stderr and validate the MP4 independently with `python3 ../../tests/verify_recording.py "$mp4" --seconds 12 --audio --synthetic-tones`. For `--seconds 1800`, also pass `--rss-log "$log"`; a valid container or a quiet track alone is not proof the two inputs survived.

The `interruption` integration suite launches only its own synthetic child process, waits for committed fragments, kills/reaps that child, remuxes the remaining closed fragments, and seeks through the result. A second case places an existing output at the intended destination before normal stop and verifies that the existing file and original fragments survive the failure. Run it separately with `cargo test -p tinyclips-media --test interruption -- --test-threads=1`.

Run the installed binary with `--seconds 1800` for an endurance check. Successful stdout contains only the final MP4 path; diagnostics, elapsed time and periodic Linux RSS/high-water readings go to stderr. This exercises the same recording, pause, segment commit and lossless finalizer as live capture, with a moving 160×120, 10 fps test image, 2-second segments for short checks (production-sized 10-second segments at durations of 60 seconds or more), and optional two distinct synthetic tones. `--seconds` is elapsed active capture time, not a fabricated file timestamp. Synthetic generators can fall behind their media clocks or stop late under emulation. A successful exit means that capture and publication completed, **not** that the real-time throughput gate passed: independently inspect both track durations, beginning/end skew, seekability, and decodable tail. Do not count an under-duration MP4 as a 30-minute recording. **This test does not validate GNOME consent, PipeWire frames, real audio devices, display resolution, real-workload endurance, or action-to-stop latency on a workstation.** Those require a separate GNOME Wayland test.
