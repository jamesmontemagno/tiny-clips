# Tiny Clips Studio for Linux

**Implementation plan, not a shipped feature.** Deliver a native GNOME Studio that produces the same editable projects and finished videos as the existing apps. Start by editing **existing footage**, not by rebuilding the recorder.

## Decisions and first proof

| Decision | What it means |
|---|---|
| **Edit first** | First demo: Clips Library → Open in Studio on an existing MP4 → set a look, cut a range, add a manual zoom, adjust volume → preview, undo/redo, export a new MP4 → reopen from the export and see the edits. Prove portable-folder import with a project from another platform in the same release track. No screen, mic or camera permission for editing existing media. |
| **Stage the camera** | Ship a useful screen editor before camera capture or segmentation is ready. Support reading/rendering an existing camera track separately from recording a new one. Don't flatten, discard, or quietly render away a camera or effect the current build doesn't support. |
| **Manual-first zooms; no invented clicks** | Manual point zooms always work. Follow a cursor only with real timestamped cursor metadata (otherwise the specified point fallback). Offer the shared click-based suggestions for imported projects that actually contain clicks; no click data means no suggestions. No cursor-motion heuristic, privileged input monitoring or shell extension. |
| **Separate Studio audio inputs** | When both are selected for a *new Studio take*, retain separate system and mic tracks; the editor can adjust each. Produce one mixed audio track on video export when sound is present. A pre-mixed imported MP4 gets master volume, not pretend stems. Ordinary Linux MP4 recording retains its existing mixed-output behavior. |
| **Native and opt-in** | Keep Rust, GTK4/libadwaita, GStreamer, GNOME Wayland and Flatpak. Use the existing settings/capture/menu vocabulary. A Studio preview toggle controls exposure; leave ordinary Screenshot and Record alone. No Linux-only project format, second MCP server, new cloud service or licensing system. |

Ground truth: the [v1 Studio specification](../docs/studio-project-format.md), [shared fixtures](../shared/studio/fixtures), [automation schema](../shared/automation/commands.json) and [integration contract](../docs/agent-integration.md). Historical design proposals are not shipped behavior. The [Linux preview](../linux/README.md) has a recorder, library and agent host, **not** a Studio implementation. A successful short clip, toolkit smoke, or emulated synthetic run is not certification of long live Studio takes. In one earlier emulated test, 1,800 seconds requested yielded about 1,095 seconds of media even though the track end times nearly matched. That is why edit-first work can proceed, but capturing new Studio projects has a separate real-input release gate; it is not a claim about the current build's maximum duration.

## User experience and parity scope

**How you get in.** Open a library video in Studio, reopen a linked export, open a recent draft, or use the document portal to open a saved project folder / `.tinyclips` document. Later, opt into **Record in Studio** from Record (not a third mode competing on the home panel); pick Region/Screen/Window through the same consent flow. Stop opens the local editor with a draft. An agent-initiated recording saves without opening an editor. No automatic camera enablement or prompts on launch.

**Rollout vs. parity.** Proposed Linux developer-preview default: Studio off until the edit-first gate passes, respecting every explicit saved on/off choice. Windows 2.0 defaults Studio on for users without an existing preference and offers a dedicated tray action. Linux intentionally keeps the two-action capture bar and nests Studio under Record. Turning Studio off must not remove projects, run cleanup, change ordinary recording/trimmer settings, or reinterpret an agent's `studio:true` request as a non-Studio recording.

**How you edit.** The video is the main surface. A native header holds project actions, Undo/Redo and Export; playback and a playhead sit below it. Keep scene, cut, speed and zoom controls near the timeline; a contextual inspector edits the selected item. At narrow widths use popovers or a collapsible inspector rather than squeezing out the preview. Preserve keyboard scrubbing/frame stepping, named controls, visible focus, non-drag alternatives and Orca-readable times/ranges. Reopening an already open project focuses its session; desktop and agent edits share one undo history. Autosave committed edits, not hover/drag samples. Distinguish **Saved draft**, **Save project**, and **Export video**. Match the [native editor actions](../windows/README.md#tiny-clips-studio-preview): scene/zoom/cut/speed lanes above a trim bar; contextual Scene, Background, Screen, Camera, Zoom, Cut, Speed, Audio and Project panels. Hide camera-only controls on screen-only footage. Space plays/pauses; arrows step frames; I/O set trim, S splits a scene, Z adds zoom, X starts a cut; provide menu equivalents. On close offer Keep Draft, Export, or explicitly confirmed discard as appropriate. Offer **Save screen recording** for a damaged draft when the clean source is salvageable.

| Area | End-state behavior |
|---|---|
| Canvas and screen | Auto/square/landscape/portrait aspects; classic and saved looks; padding, solid/gradient/image backgrounds; upright source orientation, crop, corners and shadow. Saved default looks never carry a recording-specific crop. |
| Timeline and scenes | Scrub/play/frame step, trim endpoints, multiple cuts and speed ranges; split/merge/edit scenes with cut or morph transitions. Controls indicate source versus output time. Cuts remove both picture and sound; speed changes affect scene/zoom/overlay timing consistently. |
| Zoom and overlays | Manual zoom with focus, scale and easing; edit, chain, delete and undo; click-based suggestions never overwrite manual zooms. Render real imported click rings and branding in preview and export. When available, normalize source-local cursor metadata **at capture time**, including region offset, resize and fractional scaling. A burned-in pointer must not be drawn again. |
| Camera | Separate synchronized camera video (not baked into screen); screen-only, bubble, split, camera-only layouts; anchor/offset, size, crop, mirror, shape, border, shadow and transitions. Preview and export obey camera offset, including a negative offset. Optional offline blur/removal comes last. |
| Sound | Master mute/volume; show system and mic sliders only when labels match real, independently adjustable tracks. Import *all* audio tracks, not just track zero. Mix at rate 1; non-unit speed pieces have silence of the correct output duration, not pitch shifting. No sound range envelopes, overdubbing or music tracks in the v1 parity claim: those are a [separate proposal](studio-audio-editing.md). |
| Output and lifecycle | Render a new, seekable H.264 MP4, progress/cancel, explicit destination, reopen the editable project from its export; open recent, pin, save a portable copy, safely update it, explicit deletion, and recover interrupted takes. MP4 export is not a project save. |

## Project model, files and permissions

- Add a GTK-free Rust domain crate under `linux/crates/` for project/events, validation, layout, time map, scene normalization, zoom suggestions and patching. Independent store/media/UI adapters consume it. Keep the application as composition root; no dependency from the core into GTK, the recorder, agent sockets or the library window.
- Read existing **schemaVersion 1**. Preserve unknown fields on **every nested object** and raw out-of-range values on round-trip; apply defaults, normalization and clamps when *used*. Reject unsupported future versions/invalid required data, non-finite numbers, traversal and resource-exhaustion inputs before touching assets. Use normalized top-left coordinates, even pixel sizing, explicit half-away-from-zero rounding and finite double source seconds. Verify both existing readers accept `app.platform: "linux"` before writing it and update the contract/reader tests as necessary. No schema bump just for a Linux creator.
- Store working copies under a private per-user XDG data `tinyclips/projects/<lowercase-uuid>/`: `project.json`, `screen.mp4`, optional `camera.mp4`, `events.json`, poster and owned background. The folder ID is authoritative. Persist atomically; serialize same-project saves under a revision; never derive a path from unvalidated JSON, trust another machine's absolute path, or follow an injected link. Keep Linux-only file grants, indexes, edit locks and derived preview caches out of portable data.
- An unlinked library video creates **one flat project per source path**; resolve a linked export first even before the library's index finishes loading. Reference the original, probe *displayed* dimensions/rotation and actual tracks, do not copy/delete/overwrite it. Retain edits if a disk/file/grant is unavailable; explain how to restore access. Save Project/As is disabled for external-source flat projects; exporting a video is still possible. Integrate pending-edit confirmation if entering via a trimmer once one exists.
- A portable project is a **directory**, not a ZIP or standalone movie. Import its single visible `.tinyclips` metadata file plus validated sibling assets into a fresh internal ID, empty its exports, and remember only a local association to its explicit save destination. Opening/autosave must not mutate the source. A file-only portal grant is not permission for adjacent media: request a **folder/document grant** or fail with a clear reauthorize action. Enforce the format's metadata size limit, reserved names, basename and collision rules on a case-sensitive filesystem; treat ambiguous case aliases conservatively rather than relinking or deleting the wrong video.
- Explicit **Save** updates only validated project-owned files at the remembered destination, staging assets and committing metadata last with rollback. **Save As** changes the association only after success; refuse unrelated folders, symlinks, or ambiguous replacement. Portable exports clear host `exports` and omit local state/grants. Interactive MP4 overwrite requires native confirmation for the exact selected file; recheck identity at commit, protect source/project paths, and preserve the old file on cancel, failure or a late collision. Never request blanket home access to enable portability.

## Playback and export architecture

**Integration points.** Keep document/math and safe project storage independently testable. Add a Studio media module/crate consuming that model and the GStreamer runtime; the current live recorder's segment remux is **not** a compositor for edited video. In the [GTK app](../linux/crates/app/src) register the Studio window/project-session controller and feature setting; have the [clips library](../linux/crates/clips/src) hand a validated video/ID to it instead of creating a UI dependency cycle. Preserve the [media service](../linux/crates/media/README.md)'s one-capture vs explicitly shared source distinction. The [automation host](../linux/crates/automation/src/lib.rs) currently expressly blocks `studio.export`; [capture target parsing](../linux/crates/app/src/targets.rs) rejects `studio:true`. Replace those guards only when the corresponding safe implementation and tests land.

1. **One media timeline.** Demux permitted local media, normalize orientation before layout/crop, then feed timestamped screen, optional camera and audio streams to a project session. Use container PTS, camera start offset, and the configured source frame rate, not sample index or mean frame rate. Hold a variable-rate source frame until the next starts. Resolve a single source time for all layers and events from the spec's output→source time map. Trim/cut/speed/crop are non-destructive metadata.
2. **One reference compositor.** Implement the shared layout/time math first. Prefer a CPU raster reference (Cairo/image surfaces or equivalent) fed by GStreamer decode and bounded appsink queues; emit a frame suitable for both GTK preview and the export encoder. Resolve background → styled screen/clicks → camera/mask and transitions in spec order. Test encoded-sRGB blending, alpha edges, inside borders, shadows and image fallback. Store normalized coordinates, not device-scaled widget positions. Avoid a GTK screenshot exporter or two different implementations of the same effect. Prototype this in the *installed* Flatpak; only introduce accelerated paths if measured cost requires them and reference frames still match.
3. **Preview is interactive; export is deterministic.** Decode/seek on workers, cancel obsolete scrubs using generation IDs, coalesce preview frames and use bounded thumbnail/decode caches. Pause/seek resets audio and stale buffers. GTK only presents the most recent result. In export, snapshot the revision and source handles, render by output PTS at export resolution/frame rate and stream via [GStreamer appsrc](https://gstreamer.freedesktop.org/documentation/app/appsrc.html) with backpressure to H.264/AAC/MP4. Do not drop, duplicate or pad output to conceal a timing error. Keep speed-piece silence distinct from accidentally missing audio. Stage, drain EOS, validate, publish and **only then** update the library and export link. Cancellation/disk full cannot destroy a source or existing output. Render/export must not require a live portal session or a GPU.
4. **Feature detection is honest.** Probe actual Flatpak decoders, encoders, source tracks, camera portal and cursor mode. Linux must render portable screen+camera projects once the camera renderer is ready even on a computer without a webcam. Before that, preserve a project's metadata and explain unsupported rendering; don't silently export a screen-only version. For model-dependent cutout follow the specified unmasked fallback with a visible warning; no cloud inference. Do not treat a renderer fallback as a privacy/redaction guarantee.

## Capture is a separate contract

- Keep ordinary MP4 recording and its one mixed audio track unchanged. A Studio recording writes **screen source media**, optional independent camera file, and real events, not a styled output. Use the existing session-local grant/target semantics, recorder clock, bounded work queues, segment recovery and disk budget where possible; do not add a second path around desktop authorization. Estimate enough free space for every enabled track, remux/finalization and pending export.
- Give screen, mic, system and camera a common running-time origin; source zero is the first screen frame, pauses are removed for all tracks, and input events in pauses or before frame zero are dropped. When both audio inputs were selected mux separately labelled **system then microphone** tracks into `screen.mp4`, retaining labels through segments/recovery. For one or zero inputs store the actual track list. An imported unknown/mixed list follows §7, never guessed from device order. Stop/revoke/device-loss behavior must be explicit; never substitute a mic for system playback or report a short/silent take as success.
- Publish a project only when its source media is present and verified. Maintain a private in-progress/recovery record; expose recovery of complete, aligned segments instead of publishing corrupt JSON, deleting the only good media, or presenting partial camera data as a complete take. Offer a clearly identified screen-only recovery only when it is genuinely safe. Never let cleanup erase an active or recoverable recording because its final metadata wasn't written yet.
- Add camera capture only after the Studio recording contract works: explicit [Camera portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Camera.html) access, separate remote/stream and file, verify drift and failure on unplug. An unattended request must use an already-authorized usable camera or report permission/capability failure, not open a picker. For cursor metadata use supported ScreenCast modes and real stream metadata; otherwise embedded/hidden or no samples. Real-time global buttons/keystrokes, unconditional overlay placement and guaranteed self-exclusion are **not** promised on Wayland.

## Agent Control, ownership and cleanup

Use the existing paired Unix socket → policy → app services → shared CLI/MCP. Enable meaningful actions **with** their GUI milestone, not as a final retrofit. Preserve scopes, peer/path checks, approvals, audit redaction and opt-in. Studio-off or unavailable must not expose a working command that only errors deep in rendering; `session.hello` advertises only the implemented/available commands, and direct unsupported calls return `not_supported`.

| Capability | Contract / guard |
|---|---|
| Discover and inspect | `studio.projects.list`, `studio.project.get`, `read`; IDs from the store, not filesystem paths. Return `modifiedAt` and an opaque revision. Include capability/setting detection for `studioPreviewEnabled`. |
| Edit and suggest | `studio.project.edit`, `edit`: validate an atomic patch, merge objects, replace whole arrays, protect identity/sources/pins/exports, require `expectedModifiedAt` **and** `expectedRevision`; stale writes return `conflict`. Open documents use the same undo stack. `studio.zoom.suggest`, `read`, returns a proposal only; replacing auto zooms preserves manual zooms. |
| Render | `studio.export`, `export`: new MP4 **directly in the configured video directory**, never inside project assets or over an existing output. Introduce a narrowly scoped Studio output validator, not a global relaxation of input-path restrictions. Keep cancellation/progress bounded, preserve existing CLI/MCP deadlines, and exercise concurrent edits/exports. |
| Create and manage | `recording.startVideo(studio:true)`, `record`; share existing start/status/pause/stop mechanics. Use only already-granted targets; return the saved draft ID without opening UI. Audit gaps for opening a library video as a flat project, pinning, project save/open/delete, recovery and export status/cancel. Where existing commands cannot express a meaningful action, add typed shared commands + schemas in the same milestone for platforms that implement it; use opaque IDs, approved roots/grants, and `delete`/`discard` approvals for destructive actions. OS folder/camera consent itself is a human action. Test local CLI **and** MCP discovery and calls; update the Studio skill, not just its tool descriptions. |

Library indexes projects/drafts/export links; link updates are independent of Studio visibility. Pin is immediately saved, outside document undo. Implement age/size cleanup per §12 with injected clock/storage and positive export-survival checks (path, file type, recorded size). Protect drafts, pinned/open/recording/exporting/recoverable, unsupported or unreadable, missing-export and flat projects. An inaccessible portal document counts as unavailable, not deleted. Keep the newest eligible under the size rule even if large. Keep exports/external sources when explicitly deleting an internal project. Defer enabling automatic deletion until migration, protection, interrupted recovery and disk-pressure tests pass; no cleanup while Studio is off.

## Implementation todos and release gates

Start with `ls-model` and `ls-media-spike`; these can run independently. Use the model for `ls-store` and `ls-render`, then connect both to `ls-editor` and `ls-editor-agent`. The first release gate is `ls-import-proof`. Run `ls-recorder-gate` separately: live recording reliability must not block editing existing footage, but must pass before shipping new Studio recordings.

| ID | Work and concrete exit criterion |
|---|---|
| `ls-model` | GTK-free v1 codec and pure math: load every `canvas`, `layout`, `timemap`, `autozoom`, `recording`, and real `folder` fixture. Compare every expected number at the specified tolerance and exact discrete values. Round-trip unknown fields/defaults; refuse future schema versions. Do not regenerate goldens to fit Linux. |
| `ls-media-spike` | Installed-runtime spike: decode rotated/VFR MP4, accurate seek/frame step, screen+camera samples, multiple audio tracks, CPU composite and software H.264/AAC export. Verify target resolution, frame selection, GOP seeks, preview latency, RSS and cancellation; no dependency on host codecs. |
| `ls-store` | Implement private project store, drafts, flat imports, portal grants, external portable-folder open/save and export links. Test path validation, symlink/alias/race conditions, metadata-last rollback, filename case, late collisions, offline source restoration, duplicate opens/new IDs, and unknown-field round-trip. |
| `ls-render` | Implement deterministic visuals, audio mapping and output worker. Golden-test select decoded frames (canvas, crop, rotation, transitions and zoom focus), two distinguishable audio inputs at independent gains, rate-change silence and single playable export mix. |
| `ls-editor` | Add opt-in GTK Studio window + library integration, nondestructive editing, undo/redo/autosave, keyboard transport, timeline/inspector, export progress/cancel and close confirmation. Minimum demo: open an MP4, make and undo an edit, export, seek to the result's end, reopen the editable project. |
| `ls-editor-agent` | Ship project discovery/inspection, atomic edit/suggestions and restricted export alongside the first editor release. Cover actual CLI/MCP pairing, scopes, unsupported states, stale same-second edits, protected fields, oversized inputs, concurrent export and cancellation. |
| `ls-import-proof` | Gate the **edit-first** preview: install candidate Flatpak on a clean GNOME guest; run a real Mac-authored and Windows-authored project through Linux, and reopen a Linux-authored portable snapshot in both native apps. Include redistributable media, not just JSON placeholders; inspect visual/audio output independently. Label any cross-platform leg not actually run. |
| `ls-recorder-gate` | Gate *new recording*, not import/editor work: prove the ordinary installed-pipeline duration, genuine input content, stop/seek and interrupted-file recovery. VM toolkit startup or a shorter-than-requested file with aligned track endpoints does not pass. |
| `ls-studio-record` | Add a project-aware recording sink, separate mic/system source tracks, event sampling/fallback, durable draft finalization, restart/recovery and shared capture bar/agent behavior. Ordinary recordings still export their original single mixed track. Check source loss and elapsed wall time vs actual media duration. |
| `ls-camera` | Stage camera in order: imported camera-track render/layouts/offsets → camera portal capture, pause sync and loss recovery → optional local blur/remove. Verify consent/denial, multi-track exports, screen-only fallback, model redistribution/size and CPU/GPU performance before advertising cutout. |
| `ls-lifecycle` | Ship Open Recent/library draft and export indicators, Save/As/relink, pinned projects, cleanup/storage UI, safe maintenance and matching agent workflows. Verify no loss of original footage/exports on disk pressure, cancellation or close. |
| `ls-release` | Run contract/fixture CI, installed-Flatpak media tests and the hardware/desktop matrix below. Update Linux docs/changelog, shared format/automation and Studio skill, and the relevant platform notes. Release claims reflect only passing gates; do not publish/deploy to Flathub as part of this plan. |

## Verification and limits on claims

**A small project with an exact answer:** generate a 20-second local screen clip with numbered frames and two distinguishable audio tracks. Trim to source `[2,18)`, cut `[6,8)`, and play `[10,14)` at 2×. The output must be **12 seconds**: output `[0,4)` shows source `[2,6)`, `[4,6)` shows `[8,10)`, `[6,8)` shows the accelerated piece with silence, and `[8,12)` shows `[14,18)`. Put a manual zoom at source 15s: its focus must be correct at output 9s in both preview and decoded MP4. Lower only the mic, check the system tone is unchanged outside the speed piece, and verify the original bytes and project edits survive export/reopen. This catches a plausible-looking export that silently uses the wrong clock or audio track.

- **Fast on PRs:** Rust fmt/Clippy, deterministic fixtures and lifecycle tests, ABI/CLI/MCP tests as applicable, packaged Linux build. Shared-contract changes also run existing Windows tests and both macOS schemes. Keep ordinary capture/edit tests green with Studio off.
- **Installed Flatpak:** scripted synthetic cross-platform project with rotated/VFR source, camera offset, mixed and separately labelled tones, cut/speed/zoom/morph. Compare preview frames with independently decoded export frames at boundaries (tolerances for antialiasing/segmentation, exact layout and time mapping). Verify duration against the *requested edit map*, not just video/audio agreement, decode/seek the tail, check RMS/tone content not just stream presence. Cancel mid-export or fill the destination; original/source and previous approved output survive. Synthetic project tests are valid editor proof, not camera/desktop capture proof.
- **GNOME desktop and hardware:** install on Ubuntu and Fedora Wayland, without a tray extension. A person can open/import/edit/export with no capture prompt, deny/regrant actual screen and camera, recover on source loss, and navigate timeline via keyboard/Orca at fractional scale. Run an actual **30-minute** Studio screen + selected audio take (and a camera-enabled case before camera parity); measure active elapsed vs source vs edited output, audible/visible markers near start/end, track isolation, post-warmup RSS/queue growth, space usage and tail seeking. Reopen recovered projects and verify assets independently. A 30-minute **synthetic** export or emulated run is not a real-input endurance pass. Physical GNOME testing is required before claiming camera, hardware acceleration or mixed-monitor reliability.
- **Explicitly out of scope:** a general NLE, invented click detection, arbitrary host filesystem/device access, remote rendering, special KDE/X11 hooks, and a Linux-only media/project format. Keep existing interchange, consent and the user's source footage more important than checking off a feature.
